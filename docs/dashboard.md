# Photo dashboard

- [Photo dashboard](#photo-dashboard)

The home page `/` shows photos, a clock, weather, an optional calendar, selected Home Assistant devices, Wake-on-LAN buttons, and Linkwarden bookmarks, inspired by the `dash-board` desktop application. `/dashboard`, `/dashboard/`, and `/dashboard.html` redirect to `/`. Each Settings category independently chooses Local or Global; new profiles default to Local and legacy whole-dashboard choices seed all categories. Mix Global Time with Local Weather without changing other choices. Integration credentials and managed devices retain their separate server records. See [settings scope](settings-scope.md) and [global import/export](settings-import-export.md).

**Settings** uses eight left-side tabs, each with an independent scope selector. **General** opens first and contains the scope for direct layout editing, Global transfers, and corrupt-map recovery. It no longer contains Information layout's Position or Overall scale controls; existing saved values remain supported in rendering, storage, and transfers. Use **Edit layout** on the dashboard to arrange widgets. Each widget's own panel contains its Desktop/Mobile visibility and fullscreen hiding controls. Both profiles are editable on any screen; Mobile applies up to and including 600px. Controls take effect only after that category's Save and do not disconnect services or clear selections. **Time**, **Weather**, and **Calendar** retain separate desktop/mobile scales. **Weather → Shared forecast display** controls hourly and daily forecasts across desktop, mobile, and fullscreen. **Bookmarks** contains the nested folder/link picker and Linkwarden connection controls. **Home Assistant** configures its connection and selects up to 256 dashboard devices; **Wake-on-LAN** manages saved devices. **Images** contains slideshow/background preferences and NFS status. ArrowUp/ArrowDown navigate tabs; Home/End select first/last. Long panels scroll while category Save and Close remain accessible.

Above 1000px, enabled groups use information → devices → bookmarks columns. Only visible groups reserve tracks. Both enabled device sections have equal independently scrollable rows; one enabled section uses one row, and disabling both removes the device column. At 1000px and below, enabled sections stack in information → Home Assistant → Wake-on-LAN → bookmarks order. The separate mobile preference breakpoint remains 600px. Short windows may scroll vertically to keep headings and device actions accessible. Disabling all six sections collapses dashboard content without stopping the background. **Images → Show filename** remains independent and can retain the information wrapper; changing or clearing captions updates only DOM layout, not timers or integration requests.

At viewport widths up to and including 600px, information starts near the top below the page tools and appears in time → weather → calendar order. Each view uses its own mobile show/hide setting and scale; hidden views leave no empty section. Mobile ignores desktop position, overall scale, and per-view visibility/scale values. Above 600px, information retains calendar → time → weather order; above 1000px it remains bottom-aligned. Resizing or changing orientation switches the active layout immediately without saving preferences, reloading data, or resetting photo transitions. Vertical scrolling is allowed for tall content; mobile forecast rows wrap to the available width.

These flow rules describe Automatic layout, which remains the default. Hold a widget background for 600ms or choose **Edit layout** to edit Desktop/Mobile profiles directly on the dashboard. Save, Toolbar, and Cancel stay above widgets; widgets can move underneath them without blocking access. The Custom canvas uses the full safe-area viewport without reserved control/status/caption bands. Toolbar overlays rather than shrinks it. Direct move/resize gestures and per-widget Up/Down layers require Save to persist. Entry uses a temporary Automatic template until a real change or explicit Custom selection. Save targets the captured Local or Global source with both profile drafts; a later scope change cannot redirect it. See [Arrange dashboard widgets](dashboard-layout.md) for geometry, fullscreen sizing, recovery, and ownership.

All six sections default to visible in both profiles, with mobile information scales at 1. Upgrades preserve existing hidden values and default only missing fields. Each category saves its Desktop/Mobile preferences together to its selected store; General owns both complete layout profiles. Global additionally synchronizes with revision conflicts. Each browser projects effective profiles onto its viewport without resize writes. Scale, duration, and opacity match 0.1-step controls; interval and blur use integer steps. Canonical defaults use UTC.

Fullscreen hide options default to off; hourly and daily forecasts default to shown. Upgrades fill only missing new fields in saved preferences and confirmed browser caches without rewriting records on reads or changing their revision. Existing values, including **Hide bookmarks in fullscreen**, remain unchanged. Invalid saved values are not silently replaced. Older open clients must reload before saving the expanded preference schema.

Visible pages with any Global category read shared preferences every five seconds after the previous read settles. All-Local pages read installation metadata independently without adopting Global preferences or weather location; Local Images followers read the slideshow without Global preference polling. Metadata reads do not fetch provider content or photo manifests. Hidden pages pause reads and resume current-source work when visible. Only changed values reconfigure owners; unchanged polls preserve layers/timers, and integration actions retain their independent deferrals.

Valid legacy `dashboard.preferences.v1` values now restore Local settings only; updated clients do not publish them automatically to Global. Local defaults never inherit `dashboard.shared-settings.v1`, which remains an inactive last-confirmed Global cache until Global is selected. Entering Global reads existing server values without writing them. Explicit Global saves/imports establish an uninitialized global record. Stored preference/layout compatibility decoding remains separate from strict writes.

The clock timer follows the active profile's visibility. Weather discovery and cached polling continue independently of overlay visibility. Calendar events refresh when either profile shows the calendar; hiding both pauses events without deleting the connection. Home Assistant selected snapshots, saved device metadata, and selected/loaded bookmark content retain their existing bounded refresh owners even with overlays hidden. Settings can still configure hidden services. Existing document-visibility pause/resume remains in effect; no checkbox adds an owner or cancels a submitted Wake action.

Switching tabs retains separate category drafts without saving. **Save Time settings**, **Save Weather settings**, and the other category actions validate/save only their active panel, not hidden drafts or integration forms. Widget visibility/fullscreen controls live in their owning panels. Dirty drafts retain captured revision/source while remote changes update active presentation. Writes recheck persisted category ownership; changes to another category in the same backing store can conservatively stale a draft and require explicit category reload. Failed persistence keeps confirmed values and the draft. Closing/reopening discards unsaved display drafts. Direct layout editing follows General and saves only geometry/layer data.

Home Assistant connection and Wake-on-LAN device actions save independently of **Save preferences**. Their shared server state is read immediately when Settings opens and polled every five seconds while the page is visible. Each service reads independently; a slow or unavailable service does not delay the other. Closing Settings keeps dashboard reads active; hiding the page pauses reads and resuming starts fresh reads. Propagation includes request latency and can be delayed by a pending mutation or an outage. Last confirmed state remains visible on read failure rather than pretending the configuration was removed. Home Assistant device snapshots use a separate 30-second cache-friendly loop only while selected devices exist or the picker is open. Display-only reads issue no control tokens.

These two forms preserve drafts during polling, including remote device changes. An edited device changed by another browser shows a warning; cancel and select Edit again to reload, or explicitly save your draft. Remote deletion keeps the draft without silently creating another device. Their APIs use last-successful-write semantics, not the revision conflicts used for display preferences; opaque Home Assistant configuration identity distinguishes committed credential changes without returning secrets. Affected fields are disabled during a pending action, but unrelated preferences and Close remain usable. Results from an earlier dialog session cannot clear newer drafts or move their focus. Closing clears unsent Home Assistant token input; it does not cancel or roll back an already submitted save. A timeout is an uncertain result: check saved status before retrying.

Weather city selection targets Weather scope: Local persists in this profile and queries volatile server data, while Global saves the installation location. Calendar/Linkwarden/Home Assistant connections remain server resources, with mutation controls enabled only when their respective Calendar/Bookmarks/Home Assistant category is Global. Wake-on-LAN management similarly requires Wake-on-LAN Global; normal Wake actions remain independent. Tokens/passwords stay encrypted server-side, never in preferences or exports. Unknown metadata preserves the current service snapshot. A request timeout cannot prove a server operation failed to commit. **Clear results** affects search results/status only. Timezone/format options follow Time scope and govern weather/calendar timestamps too; actual fullscreen entry, folder disclosure, and drafts remain session interactions.

Selected Linkwarden links appear as a flat list without parent folders, in a right-side desktop column or stacked page flow. Settings retains nested folders and individual link checkboxes; its disclosure is session state. The old mobile Compact/Expanded preference remains stored for compatibility, without a display control or effect on the flat list. **Hide bookmarks in fullscreen** lives under **Bookmarks → Display**. Each widget's fullscreen hide option combines with its active desktop/mobile visibility: it can hide an enabled widget but cannot reveal a disabled one. Exiting fullscreen restores only widgets enabled by the current profile. Automatic and Custom layouts honor these choices without changing saved geometry. Display-only saves preserve photos and existing integration owners. See [Linkwarden bookmarks](linkwarden.md) for catalog behavior.

The server discovers JPEG, PNG, WebP, and GIF backgrounds on its optional read-only NFS share within existing metadata/stream limits. Local browsers follow the Global server-owned sequence by default, including existing profiles without an explicit choice. Turn off **Images → Show the same image as Global** and save for independent Local playback through a server-filtered eligible manifest. Global selection advances even with no viewers. Local presentation remains independent; Local Order/Interval are disabled but preserved while following. Random traversals avoid immediate cycle-boundary repeats for multi-image pools. Server restarts create a fresh shared sequence using saved Global preferences.

Discovery admits up to 5,000 directory entries across at most eight directory levels and accepts at most 100 files within 20 MiB-per-image/200 MiB-total limits. Directories, unsupported entries, and symlinks consume admission budget; eligible filename filtering can reduce the playable pool further. Settings reports how many backgrounds are in that bounded pool, not the total number on the NAS. Even a 7,000-image export can therefore report a pool of 100. Already-admitted candidates are processed after enumeration fills its budget, including parent siblings after nested exhaustion. Sorting/random traversal apply to the admitted eligible subset, not every image on the export. No eligible results within a capped scan do not prove that the entire share is empty.

Global browsers and Local followers read `/api/dashboard/slideshow?version=2` within a five-second polling cap; wakes read state without advancing it. Independent Local browsers refresh `/api/dashboard/photos/local` every sixty seconds and rotate without reconfiguring the shared cursor. Hidden/persisted pages pause their browser work and resume their active source. Presentation changes keep current DOM layers, and transitions respect reduced motion. Saving a playback-source change clears the previous frame until replacement loading succeeds. Failed metadata/image reads within an unchanged source retain last-good backgrounds; confirmed disabled/empty sources clear them. Shared selection does not guarantee frame-perfect synchronized transitions. Single-image pools have no rotation loop. See [NFS backgrounds](nfs-backgrounds.md).

Only the current image needs decoding/display at a time. One `current` record or one initial image download does not imply a one-image pool; inspect the metadata count and subsequent selection changes. Scan deadlines remain cooperative, and actual discovery failures stay unavailable/stale rather than becoming successful partial scans.

Search for a city in **Settings → Weather**. Geocoding goes directly from the browser to [Open-Meteo](https://open-meteo.com/); forecast/AQI retrieval remains server-side. In Global, SQLite stores the city and latest successful data, with startup/hourly retrieval continuing without viewers. In Local, the city is browser-local and `/api/weather/local` queries a bounded volatile cache without changing Global rows. Local retrieval is demand-driven; retained-key attempts are hourly and failed parts preserve same-source successful data. Both modes show successful update times and poll pending work independently.

The transparent weather overlay pairs visible condition text with local SVG artwork for current conditions, three-hourly samples of the next 24 hours, and seven daily forecasts; it does not request icons from another service. Hourly icons follow Open-Meteo's day/night flag, while daily icons use daytime variants. The artwork is bundled from the sibling `dash-board` project. The page also shows the **US AQI**, with air-quality data attributed to [CAMS ENSEMBLE](https://ads.atmosphere.copernicus.eu/). **Updated** shows when the server last successfully retrieved the displayed forecast, formatted with a date in the dashboard timezone and 12/24-hour format. It is not the provider observation time; failed refreshes and air-quality-only updates do not advance it.

Both weather scopes use a dedicated server transport with a two-second address-family connection-attempt window, avoiding premature failure on slower IPv4 routes when IPv6 is unreachable. This changes only weather connections, preserves TLS verification and the ten-second request deadline, and closes the owned connection pools on shutdown. No additional provider or API key is required. A valid AQI of zero displays normally. Air quality remains independent of forecast success; failed refreshes retain a prior same-location reading with **stale; refresh failed**, while **Air quality unavailable** means no valid reading is cached. Attempts remain hourly, and a successful attempt clears the air-quality error. Restarting the updated server triggers Global startup retrieval; Local retrieval starts when its location is requested.

On Node releases with built-in environment proxy support (24.5 or later), weather follows Node's initialized proxy opt-in: enable `NODE_USE_ENV_PROXY=1`, use `--use-env-proxy`, or set it through `NODE_OPTIONS`. Node resolves explicit negative flags and startup precedence; setting `HTTP_PROXY` or `HTTPS_PROXY` alone does not enable routing. Enabled weather requests use `HTTP_PROXY`/`HTTPS_PROXY` and `NO_PROXY` through Undici's environment proxy agent, with lowercase variables taking precedence. Exact hosts, domain suffixes, matching ports, and `*` can bypass the proxy. `*.example.com` bypasses both `example.com` and its subdomains; an attached numeric port restricts bypass to that port. Existing transports read `no_proxy` or `NO_PROXY` again for each dispatch, including empty lowercase overrides and deletion fallback to uppercase. A lazily allocated direct pool supplies Node's wildcard domain-itself behavior while other matching remains with Undici. For example, launch with `NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://proxy.lan:3128 npm start`; proxy credentials remain outside documentation and Git. Earlier Node 24 releases without this native policy retain direct weather connections. Direct, bypass, proxy, and tunneled target connections retain the scoped two-second attempt setting and normal TLS validation. Invalid enabled proxy settings fail rather than silently switching to direct egress. Global and Local services each destroy their own direct/proxy pools, including the supplemental wildcard pool, after pending work settles; repeated transport stop calls share completion and await all owned destruction attempts. Caller-injected fetch resources remain caller-owned.

**Show hourly forecast** and **Show daily forecast** work independently. Disabling both removes the forecast area while retaining current conditions, air quality, and the successful forecast's Updated time. Re-enabling a list uses the latest available data or its unavailable message; visibility changes do not request another provider refresh. Later weather updates and shared preference changes retain the saved visibility choices.

Temperature, wind, and precipitation units follow Weather scope and reproject canonical data without another provider refresh. Timezone follows Time scope and can select a different provider timezone variant without changing Weather's city ownership. The persisted Global service retains at most eight timezone variants plus one AQI snapshot; the separate Local service admits at most sixteen volatile coordinate/timezone keys. Weather polls every five seconds while pending and sixty seconds otherwise. Global provider work continues while pages are hidden; Local browser demand pauses. The public provider endpoints and usage terms still apply.

**Enter fullscreen** uses the browser Fullscreen API and may be unavailable or denied by browser policy. Escape exits fullscreen. **Edit layout** is hidden in fullscreen; long press still works on visible widgets, or enter editing before fullscreen. Editing retains Save/Toolbar/Cancel and its fullscreen toggle. Immersive fullscreen hides other page tools unless no effective dashboard sections remain visible; then **Settings** and **Exit fullscreen** stay reachable, including caption-only pages and pages with every widget hidden by fullscreen options. Filename captions remain independent. Fullscreen visibility changes only presentation, not clock timers, service eligibility, or slideshow playback. The dashboard uses native browser modules without a build step, Tauri, or a runtime dependency on the reference checkout.
