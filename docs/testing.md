# Checks

```sh
npm test
npm run check
npm run test:browser
```

The tests validate CalDAV discovery/protocol handling, configuration migration, private-CA TLS and encrypted credentials, Home Assistant WebSocket handling, Wake-on-LAN packets, Linkwarden trees/caching, weather persistence/deadlines, and API behavior. Shared-settings checks cover atomic migration and competing revisions, complete canonical preferences, unavailable integration isolation, cached/offline behavior, delayed observer guards, per-service metadata deferral, visibility lifecycle, and configuration adoption.

Browser tests retain desktop/mobile layouts, service data, bookmark disclosure, cached weather timestamps, forms, and fullscreen. New multi-client cases use independent contexts against a real local server/store for cross-category changes, conflicts/drafts, legacy migration, remote weather/calendar/Linkwarden configuration, and live preference updates during a pending connection. A focused case launches actual Firefox alongside Chromium and checks propagation in both directions. Providers are injected or intercepted; no live integration account is required.

Integration Settings tests cover Home Assistant connect/re-authenticate/disconnect and URL/token rules, Wake-on-LAN device CRUD, duplicate MAC and IPv4 errors, confirmed audit deletion, server restart persistence, dirty drafts, delayed old-session results, independent polling, and hidden/persisted-page resumption. The runner starts the production server through IPC and uses its normal shutdown handler without requiring OS signal permission. Set `PLAYWRIGHT_PORT` to another free port if an old interrupted runner still owns port 3210, for example `PLAYWRIGHT_PORT=3212 npm run test:browser`. Stop stranded older runners from a shell with permission; no elevated operations are performed by these tests.

Shutdown tests exercise startup interruption, repeated requests/signals, deadlines, HTTP admission, unfinished uploads, keep-alive sockets, handler/audit/queued-mutation drainage, cleanup failures, SQLite ordering, and simulated NFS children through the existing command seam. No real mount operation is used. Development tests use temporary source trees and isolated databases, with fresh-child env precedence, actual private-CA HTTPS trust across reloads, failed-edit recovery, readiness, IPC loss, and parent/child timeout ordering.

NFS existing-mode fixtures also cover default NFSv3 `rw,hard,timeo=600` mounts, read-only binds retaining that hard retry policy, and safe read-only binds with bounded soft retries. Unsafe topology must be rejected before file access and existing mode must not invoke mount. These are simulated mountinfo checks, not live TrueNAS verification. Follow the operator-controlled staged checks in [NFS backgrounds](nfs-backgrounds.md) for a live export; never make ordinary tests depend on the NAS or assume a shell timeout cancels a kernel filesystem operation.

Process tests distinguish three mechanisms: IPC/self-emitted lifecycle signals, userspace OS signal delivery, and actual terminal/process-group Ctrl+C. Ctrl+C integration cases cover direct development and `npm run dev` only; production retains SIGTERM and IPC/disconnect verification, with its existing SIGINT handler unchanged. Owned-process SIGINT/SIGTERM probes are explicitly skipped with a capability diagnostic if the environment returns `EACCES`. Python 3's standard-library `pty` module drives terminal cases when installed and supported; install Python 3 through the operator if that verification prerequisite is absent. Terminal delivery can succeed when a userspace `kill()` is denied. Tests check only owned PIDs, ports, and temporary directories for leftovers/core artifacts.

The PTY driver preserves the wrapper's wait status and drains terminal output after wrapper exit. The npm SIGINT outcome (`-2` from Python on the verified Linux runtime) is accepted only with intentional Ctrl+C, complete output, a successful non-forced server lifecycle result, normal supervisor exit zero, no watchdog fallback, no remaining owned processes, and immediate port reuse. Direct development must exit zero. Missing evidence, other signals, application/cleanup failures, timeouts, native crashes, and new core artifacts fail. An npm `kill EACCES` outcome remains an explicitly reported permission limitation and still requires independent application-cleanup evidence. Test-only preload records contain only process identity and allowlisted lifecycle fields; no production monitoring API or signal interception is added.

`test/terminal-shutdown.test.js` covers rejected outcome combinations, raw SIGINT status, late descendant output, and bounded driver timeout. Its Linux late-output fixture uses a test-only child subreaper through Python's standard-library `ctypes` to reap its own short-lived orphan rather than leave it to container PID 1; it does not signal unrelated processes or change container privileges.

For bounded local verification use `npm test -- --test-timeout=10000`; terminal cases have their own longer bounded driver/fixture deadlines. Deferred fixture waits also have short explicit deadlines. A signal-denied environment cannot forcibly clean a permanently blocked process; fixtures must remain cooperative and tests must not create such a process intentionally.

Install development dependencies with `npm ci`, then download both required browsers with `npx playwright install chromium firefox`. The default runner is Chromium, with Firefox launched only by the focused cross-engine case. Container system libraries must be installed by the operator when missing; do not silently skip engine verification. A safe packet-dispatch integration test still requires a disposable UDP receiver on the deployment network.

Selected-bookmark tests cover shared choice persistence, never-configured versus empty preferences, exact bounded records, source/account identity, token renewal, selected-first cache reclamation, late-response protection, and genuinely over-budget content. Real-server browser cases cover checkboxes nested beneath their Settings folder branches, a flat selected-only dashboard without parent labels, mouse/keyboard loopback popup navigation with no opener, restart and two-browser synchronization, dirty-draft conflicts, explicit moved-link hint repair/discard, access-denied label removal, the 256-link picker limit, and desktop/mobile/fullscreen presentation. Providers are stubbed and popup destinations remain loopback; no real Linkwarden account is contacted.

Background-display checks cover strict six-boolean schema upgrades without read-time writes, old confirmed caches, independent profiles, all 64 overlay combinations, collapsed grid tracks/device rows, and DOM-only caption application. `e2e/background-display-options.spec.js` uses isolated SQLite/real servers for checkbox saves, restart persistence, two-client dirty-draft conflicts, 600px/1000px boundaries, 320–1200px geometry, and background-only/caption-only fullscreen tools. Slideshow tests retain clock interval identity and request owners across repeated captions. Device tests hide/re-enable overlays during a stubbed pending Wake and retain snapshots/audit ownership; bookmark tests retain selected flat links, new-tab attributes, and photo layers. Providers are stubbed; no real broadcast packet or NFS mount is used.

Custom widget layout tests cover the bounded unit schema, strict nested writes, old-record/cache defaults without read writes, layer order, deliberate overlap, projection limits, and field-specific edits that preserve unrelated canonical values. Bottom-left regressions verify upward Y/move/resize behavior and a stable bottom anchor across window changes. Version-1 top-origin records/caches convert once to version 2 without read-time writes, while old-coordinate PUTs receive a reload error. The minimum-clamp regression verifies that moving a 100,000-unit-wide card on an 800px surface never changes its 160px width on a 1600px surface. View tests retain actual node identity and restore Automatic groups, coalesce measurement frames, handle all-hidden surfaces, and dispose observation ownership. `e2e/dashboard-layout.spec.js` exercises real drag/resize and touch capture, Escape cancellation, numeric/keyboard edits, covered-widget hit testing, shared conflicts, failed saves, restart persistence, small/rotated/fullscreen windows, internal scrolling, and clock/slideshow ownership. A focused Firefox/Chromium case verifies shared canonical layouts with per-window fitting. Fixtures use owned temporary storage and stubbed content/actions, never real integrations or Wake packets.

Automatic-key checks cover pure no-write configuration, database-relative defaults, restricted parent/file creation, atomic winner races, partial-write/publication cleanup, explicit-secret precedence, restart credential continuity, and lost-key refusal. Home Assistant TLS checks use `HOME_ASSISTANT_CA_FILE` for real loopback registry/service sessions, hostname verification, unrelated HTTPS trust isolation, and actual development-child trust changes. No live account, key, database, mount, or user `.env` is used.

Run `node scripts/check-production.js` for the opt-in packaging smoke. It copies only runtime/manifests into `/tmp/opencode`, installs locked production dependencies there, verifies local Undici resolution and absence of Playwright, then checks actual readiness/HTTP/automatic key/IPC shutdown with isolated storage and disabled NFS. It never replaces the working dependency tree. Registry/tooling failures are reported; a passing production-tree smoke is not built-image verification. Compose configuration parsing and actual image build/runtime checks remain separately recorded.
