The tests validate CalDAV discovery/protocol handling, configuration migration, private-CA TLS and encrypted credentials, Home Assistant WebSocket handling, Wake-on-LAN packets, Linkwarden trees/caching, weather persistence/deadlines, and API behavior. Shared-settings checks cover atomic migration and competing revisions, complete canonical preferences, unavailable integration isolation, cached/offline behavior, delayed observer guards, per-service metadata deferral, visibility lifecycle, and configuration adoption.

Browser tests retain desktop/mobile layouts, service data, bookmark disclosure, cached weather timestamps, forms, and fullscreen. New multi-client cases use independent contexts against a real local server/store for cross-category changes, conflicts/drafts, legacy migration, remote weather/calendar/Linkwarden configuration, and live preference updates during a pending connection. A focused case launches actual Firefox alongside Chromium and checks propagation in both directions. Providers are injected or intercepted; no live integration account is required.

Integration Settings tests cover Home Assistant connect/re-authenticate/disconnect and URL/token rules, Wake-on-LAN device CRUD, duplicate MAC and IPv4 errors, confirmed audit deletion, server restart persistence, dirty drafts, delayed old-session results, independent polling, and hidden/persisted-page resumption. The runner starts the production server through IPC and uses its normal shutdown handler without requiring OS signal permission. Set `PLAYWRIGHT_PORT` to another free port if an old interrupted runner still owns port 3210, for example `PLAYWRIGHT_PORT=3212 npm run test:browser`. Stop stranded older runners from a shell with permission; no elevated operations are performed by these tests.

Shutdown tests exercise startup interruption, repeated requests/signals, deadlines, HTTP admission, unfinished uploads, keep-alive sockets, handler/audit/queued-mutation drainage, cleanup failures, SQLite ordering, and simulated NFS children through the existing command seam. No real mount operation is used. Development tests use temporary source trees and isolated databases, with fresh-child env precedence, actual private-CA HTTPS trust across reloads, failed-edit recovery, readiness, IPC loss, and parent/child timeout ordering.

NFS existing-mode fixtures also cover default NFSv3 `rw,hard,timeo=600` mounts, read-only binds retaining that hard retry policy, and safe read-only binds with bounded soft retries. Unsafe topology must be rejected before file access and existing mode must not invoke mount. These are simulated mountinfo checks, not live TrueNAS verification. Follow the operator-controlled staged checks in [NFS backgrounds](nfs-backgrounds.md) for a live export; never make ordinary tests depend on the NAS or assume a shell timeout cancels a kernel filesystem operation.

Process tests distinguish three mechanisms: IPC/self-emitted lifecycle signals, userspace OS signal delivery, and actual terminal/process-group Ctrl+C. Ctrl+C integration cases cover direct development and `npm run dev` only; production retains SIGTERM and IPC/disconnect verification, with its existing SIGINT handler unchanged. Owned-process SIGINT/SIGTERM probes are explicitly skipped with a capability diagnostic if the environment returns `EACCES`. Python 3's standard-library `pty` module drives terminal cases when installed and supported; install Python 3 through the operator if that verification prerequisite is absent. Terminal delivery can succeed when a userspace `kill()` is denied. Tests check only owned PIDs, ports, and temporary directories for leftovers/core artifacts.

The PTY driver preserves the wrapper's wait status and drains terminal output after wrapper exit. The npm SIGINT outcome (`-2` from Python on the verified Linux runtime) is accepted only with intentional Ctrl+C, complete output, a successful non-forced server lifecycle result, normal supervisor exit zero, no watchdog fallback, no remaining owned processes, and immediate port reuse. Direct development must exit zero. Missing evidence, other signals, application/cleanup failures, timeouts, native crashes, and new core artifacts fail. An npm `kill EACCES` outcome remains an explicitly reported permission limitation and still requires independent application-cleanup evidence. Test-only preload records contain only process identity and allowlisted lifecycle fields; no production monitoring API or signal interception is added.

`test/terminal-shutdown.test.js` covers rejected outcome combinations, raw SIGINT status, late descendant output, and bounded driver timeout. Its Linux late-output fixture uses a test-only child subreaper through Python's standard-library `ctypes` to reap its own short-lived orphan rather than leave it to container PID 1; it does not signal unrelated processes or change container privileges.

For bounded local verification use `npm test -- --test-timeout=10000`; terminal cases have their own longer bounded driver/fixture deadlines. Deferred fixture waits also have short explicit deadlines. A signal-denied environment cannot forcibly clean a permanently blocked process; fixtures must remain cooperative and tests must not create such a process intentionally.

Install development dependencies with `npm ci`, then download both required browsers with `npx playwright install chromium firefox`. The default runner is Chromium, with Firefox launched only by the focused cross-engine case. Container system libraries must be installed by the operator when missing; do not silently skip engine verification. A safe packet-dispatch integration test still requires a disposable UDP receiver on the deployment network.

Selected-bookmark tests cover shared choice persistence, never-configured versus empty preferences, exact bounded records, source/account identity, token renewal, selected-first cache reclamation, late-response protection, and genuinely over-budget content. Real-server browser cases cover checkboxes nested beneath their Settings folder branches, a flat selected-only dashboard without parent labels, mouse/keyboard loopback popup navigation with no opener, restart and two-browser synchronization, dirty-draft conflicts, explicit moved-link hint repair/discard, access-denied label removal, the 256-link picker limit, and desktop/mobile/fullscreen presentation. Providers are stubbed and popup destinations remain loopback; no real Linkwarden account is contacted.

Background-display checks cover strict six-boolean schema upgrades without read-time writes, old confirmed caches, independent profiles, all 64 overlay combinations, collapsed grid tracks/device rows, and DOM-only caption application. `e2e/background-display-options.spec.js` uses isolated SQLite/real servers for checkbox saves, restart persistence, two-client dirty-draft conflicts, 600px/1000px boundaries, 320–1200px geometry, and background-only/caption-only fullscreen tools. Slideshow tests retain clock interval identity and request owners across repeated captions. Device tests hide/re-enable overlays during a stubbed pending Wake and retain snapshots/audit ownership; bookmark tests retain selected flat links, new-tab attributes, and photo layers. Providers are stubbed; no real broadcast packet or NFS mount is used.

Custom widget layout tests cover the bounded unit schema, strict nested writes, old-record/cache defaults without read writes, layer order, deliberate overlap, projection limits, and field-specific edits that preserve unrelated canonical values. Bottom-left regressions verify upward Y/move/resize behavior and a stable bottom anchor across window changes. The minimum-clamp regression verifies that moving a 100,000-unit-wide card on an 800px surface never changes its 160px width on a 1600px surface. View tests retain actual node identity and restore Automatic groups, coalesce measurement frames, handle all-hidden surfaces, and dispose observation ownership. `e2e/dashboard-layout.spec.js` exercises real drag/resize and touch capture, Escape cancellation, numeric/keyboard edits, covered-widget hit testing, shared conflicts, failed saves, restart persistence, small/rotated/fullscreen windows, internal scrolling, and clock/slideshow ownership. A focused Firefox/Chromium case verifies shared canonical layouts with per-window fitting. Fixtures use owned temporary storage and stubbed content/actions, never real integrations or Wake packets.

Tiny-widget regressions use test-only controlled screen/visual viewport dimensions while retaining real markup, CSS, observers, and application initialization. Automatic-key checks cover pure no-write configuration, database-relative defaults, restricted parent/file creation, atomic winner races, partial-write/publication cleanup, explicit-secret precedence, restart credential continuity, and lost-key refusal. ## Photo inventory memory benchmark

Run `node --expose-gc scripts/benchmark-photo-library.js` in three fresh processes. The benchmark creates and removes 7,001 local 68-byte PNGs under `/tmp/opencode`, captures a pre-inventory baseline, traverses 7,001 unique filenames through cooperatively prepared metadata batches, warms a complete virtual playback cycle, then measures five unchanged refreshes and one replacement generation. The additional sequencer drains and releases its queues before the warm settled sample. Output includes queue capacity after commitment, queued metadata bytes, preparation durations, Node version/architecture, real scan durations, sampled RSS/heap peaks at cooperative scan/transform/preparation batches and publication, Linux `/proc/self/status` `VmHWM` for the current process-image RSS peak, and GC-settled samples after grace expiry. `process.resourceUsage().maxRSS` is also recorded because it can retain the launching harness's pre-exec high-water mark; it is not substituted for `VmHWM`. Explicit GC is limited to this opt-in benchmark; ordinary tests and production never depend on it.

Each run must keep peak RSS increase within 128 MiB of the pre-inventory baseline and final settled heap growth within the larger of 4 MiB or 10% of the warm settled heap. These task targets are measured evidence, not universal resource guarantees. Deterministic tests cover budget admission, staging discard, token expiry, and actual drain ownership. Benchmark RSS is deliberately separate from unit assertions and browser decoding memory. Record actual outputs in the task implementation record. Raspberry Pi/NFS count, late-file playback, scan timing, RSS, and available-memory validation remain separate operator/device checks when target access is unavailable.

## Photo lookahead and browser resources

Run `node --test test/photo-batch-sequence.test.js test/photo-lookahead.test.js test/photo-slideshow.test.js test/photo-slideshow-data.test.js test/photo-slideshow-api.test.js test/local-photo-manifest-api.test.js test/shutdown.test.js`. Deterministic cases cover empty/single/two/small/exact/partial/7,001-file pools, two complete random cycles, filename reconciliation, bounded UTF-8 batches, interval/order changes, reservation versus commitment, failed/deferred fills, and actual stop/drain ownership. Transport checks retain strict version 1 and negotiate version 2 with distinct current/queue revisions, nullable previews, bounded snapshots, and unsupported-version rejection.

Follower tests use retained/deferred resources to verify no early display, no duplicate decode, current-priority fallback, ready/in-flight promotion, obsolete resource release, retry deadlines, unchanged-current work during preview changes, stale queue guards, and suspension. Delayed Global previews arrive through one 500-millisecond readiness poll path with five-second error recovery. Local fill notifications work without automatic HTTP polling, including completion during snapshot consumption and hidden/resumed delivery. Preview updates retain the current frame and selection deadline.

Run `npm run test:browser -- e2e/server-photo-rotation.spec.js e2e/photo-display-recovery.spec.js`. Controlled delayed-fill cases first consume a null preview, release preparation, and observe actual upcoming image requests before the five-second selection deadline. Both owners cross an exhausted metadata-batch boundary; Local never advances Global. The production Global view must adopt the exact decoded element only when selected, and initial requests must remain current plus immediate next.

The `large-image resource` case in `e2e/server-photo-rotation.spec.js` uses actual elapsed browser time, generated 2048×1536 PNG responses, repeated production-view promotions, one-second fades, blur backgrounds, and a stalled then invalid upcoming response. It prints `photoBrowserBenchmark` JSON with compressed dimensions/bytes, estimated RGBA bytes per image, actual request count, decode durations, and foreground/blur/speculative/released ownership samples. Weak references observe detached decoded elements without retaining a hidden image batch. Assertions bound foreground/outgoing layers to two, blur layers to two, and speculative ownership to one, while cleared source counts increase. This checks application ownership, not browser-process RSS or physical-device decode headroom; browser/OS caches may retain memory independently.

On an accessible Raspberry Pi 5/NFS target, separately observe a complete nonrepeating filename traversal, files added after startup, scans approximately 60 seconds after previous scan settlement, and process/available-memory headroom during transitions with representative full-resolution images. Record corrupt/slow-file held-frame recovery and one-image lookahead at the minimum interval. Without target access, record these hardware checks as pending rather than inferring them from local fixtures.

## Direct layout editing

Activation unit tests inject timers and realistic pointer inputs for threshold, screen-space movement, lifecycle/scroll/second-pointer cancellation, eligibility/hit rechecks, context-menu scope, release/click suppression, stale callbacks, and cleanup. Pure session tests verify Automatic no-op templates, exact cancellation, profile independence, immutable complete baselines, revision capture, and explicit offline reload. View tests retain the separate confirmed snapshot while projecting a local pinned-profile override, then restore the latest confirmation.

The existing 22 layout browser scenarios now use direct controls or retain view-only assertions rather than the removed Settings preview. Additional real-browser tests use trusted mouse and CDP touch input, controlled clock time, real-server SQLite revisions, request payload counters, and actual popup/action fixtures. They cover long press, native touch scrolling, click-through safety, keyboard/fullscreen access, hidden/inactive profiles, polling-safe raw fields and gestures, pending writes, conflicts/failures, no-op saves, and unrelated Settings layout preservation. A stubbed Wake starts before editing and completes under inert roots; synthetic stale clicks cannot dispatch another action. No real Wake packet, provider account, or mount is used. Desktop browser touch emulation does not verify physical pen hardware, mobile Safari, or OS touch callouts.

Unchanged-size editing tests retain all 34 task 52 layout scenarios while distinguishing edit entry from opening details. They compare normal, editing, panel-open, panel-closed, and post-Cancel canvas/card/text measurements across desktop/mobile, wrapped tools, captions, and fullscreen, with zero writes. View tests exclude chrome from measurement/observer ownership without freezing real viewport changes. Panel tests verify raw valid/invalid values, focus, scrolling, Escape/Close, and capture-preserving toggles. Per-widget layer tests check explicit targets, both profiles, one-step Up/Down, boundary disabling, exact canonical rectangles, covered/tiny alternatives, and normal save/restart ownership. Native short-window tests keep compact exits outside panel scrolling.
