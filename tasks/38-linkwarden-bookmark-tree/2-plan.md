# plan

## scope

Restore a Linkwarden bookmark interface on the photo dashboard as specified in `1-goal.md`: an expanded right-side tree on desktop, root-expanded/child-collapsed Compact mode on mobile, an optional fully Expanded mobile mode, and a saved Hide bookmarks in fullscreen option. Reuse the existing encrypted connection and collection-specific APIs. Add Settings connection controls, bounded loading, stale/partial failure states, token recovery, and verification. The current dashboard has no bookmark frontend; the backend already builds nested collections and caches paginated bookmarks. Keep the existing clock, weather, calendar, photo, and mobile display behavior working.

## Implementation Plan

### 1. Define preferences, folder identity, and bounded tree data

- Extend `normalizeSettings` in `public/dashboard-helpers.js` with `mobileBookmarksMode`, accepting only `compact` or `expanded` and defaulting to `compact`, and `hideBookmarksFullscreen`, accepting only a boolean and defaulting to `false`. Keep `dashboard.preferences.v1`, existing desktop/mobile fields, and the generic preferences form/save path. Loading defaults does not write storage. Access tokens and opaque collection request tokens must never enter display preferences.
- Add a DOM-free `public/bookmark-data.js` for the public tree/bookmark validation, default expansion policy, and shared bounds. A public collection node contains `selectionId`, `name`, `collectionToken`, and `children`; bookmark records retain the existing numeric bookmark ID, bounded name, and HTTP(S) URL. Treat collection tokens as replaceable request credentials, not stable folder identities. Validate repeated IDs, malformed children, excessive depth/count, and unsafe links before exposing browser state.
- Use a maximum of 256 collections and depth 16, checked before recursive tree processing. Reject an oversized/deep collection graph with a clear limit state instead of silently flattening or presenting an incomplete hierarchy. Preserve existing orphan/cycle handling within those bounds. Bound each collection result to 2,000 bookmarks and 2 MiB of serialized bookmark data, returning an explicit `truncated` flag when the complete result exceeds either bound. Account bytes incrementally rather than repeatedly serializing the growing list.
- Bound browser-held bookmark content to 10,000 links and 8 MiB of normalized name/URL/ID data across the current tree. Stop adding further content and stop queuing additional unloaded folders at that budget, preserve the accepted prefix, and show a clear limit notice with a link to the configured Linkwarden site. Account replacement of existing folder content by releasing its previous contribution before applying its replacement, so routine refreshes do not accumulate duplicate budget usage. Do not label a limited result as an empty folder. These are fixed implementation bounds, with their behavior documented and tested.
- Define mobile Compact defaults as open depth-zero collections and closed descendants; Expanded defaults open every folder. Keep session-only disclosure overrides keyed by `selectionId` separately for desktop-expanded, mobile-compact, and mobile-expanded profiles. Newly discovered folders receive the relevant default. Folder names, duplicate labels, or rotating tokens must not be used as keys. Fullscreen hiding does not reset any profile's overrides.

### 2. Extend the existing server API for stable identity and connection-safe results

- In `src/app.js`, add a stable opaque `selectionId` to each collection node, derived with a namespaced SHA-256 hash of the normalized Linkwarden base URL, username, and collection ID. It must survive token renewal, rename, and ordering changes within the same account. Continue issuing the existing short-lived, fingerprint-bound `collectionToken`; clients still cannot request arbitrary numeric collection IDs.
- Add an opaque `configurationId` to Linkwarden status and successful tree/bookmark responses. Derive it from the stored URL, username, and encrypted credential record, including its random IV/ciphertext/tag, rather than returning plaintext credential material or relying on second-resolution `updatedAt`. This identity survives server restart and changes on each successful configuration save without adding a database migration. Return `null` when no saved configuration exists.
- Capture the saved configuration identity before asynchronous tree/bookmark retrieval and compare it before issuing tokens or returning data. If a successful reconnect/disconnect changed the configuration meanwhile, return 409 with `code: 'LINKWARDEN_CONFIGURATION_CHANGED'` and no old-account contents. Include the captured matching configuration ID in normal results. The browser must compare it with its current source before installing any response.
- Return `code: 'COLLECTION_SELECTION_EXPIRED'` alongside the existing 400 invalid-selection message when a token is expired, evicted, or no longer resolves. Preserve existing routes and messages for older API clients; the new identity/status fields and structured error codes are additive.
- Serialize Linkwarden PUT and DELETE mutations in the existing server style used for Home Assistant and CalDAV. A PUT validates credentials and collections before saving; failures keep the previous configuration, tokens, and usable cache. A DELETE queued after a pending PUT runs after it and leaves the installation disconnected. Clear integration cache and selection tokens only after successful committed configuration changes.
- Keep network/Host/Origin checks, bounded JSON input, encryption-key handling, scoped private-CA trust, and server-only Bearer authorization. Preserve connect-with-empty-token behavior only when URL and username are unchanged. Settings uses the existing status flags for unavailable encryption, saved but unreadable credentials, and reconnect requirements.

### 3. Bound paginated retrieval and cache ownership for a multi-folder consumer

- Extend `src/linkwarden.js` only where the new whole-tree consumer requires bounded behavior. Retain the current search endpoint, 1,000,000-byte provider-response limit, deduplication by bookmark ID, repeated-cursor detection, and maximum 100 pages. Apply the collection count/depth bounds before building the recursive tree, and the per-folder count/serialized-size bounds while accumulating bookmarks. Include `truncated` metadata in cache entries and stale results when a limit was reached.
- Keep the existing eight-second per-request deadline active through body consumption: `request` must await `boundedJson` before clearing its timer. Add a twenty-second total deadline for a collection's paginated retrieval. Propagate cancellation through the page loop and cancel/release response bodies or abort transport work on early status/Content-Length rejection, streamed-size failure, parsing failure, and timeout. No abandoned body or page loop should outlive its owning request deadline.
- Bound the server's collection bookmark cache to 32 MiB and 64 entries using least-recently-used eviction. Account normalized payload size when replacing entries, retain the existing 60-second freshness policy, and keep same-key requests coalesced. Failed transient refreshes retain the latest usable same-configuration result; successful configuration changes invalidate cache generations so late work cannot repopulate them.
- Classify provider 401 as re-authentication and 403 as access denied instead of allowing either to fall back to cached protected content. Propagate safe structured codes through the collection/bookmark API without upstream response bodies or credentials. A folder-level access denial clears that folder's usable contents; other accessible folders remain usable. A denied collection listing or authentication failure prevents displaying the old tree until access is restored through a successful reconnect or a detected configuration change.
- Apply that access-failure policy to reads of the committed configuration. A rejected provisional PUT with a bad replacement token must report a connection failure without invalidating the existing saved account's cache or disclosure state; the new credentials have not become the current source.
- Keep the normal small-result API shape compatible with existing consumers. Return `truncated: true` only when applicable, and expose a safe collection-limit error when the hierarchy cannot be represented within bounds. Extend existing Linkwarden tests for these new limits and failure distinctions rather than replacing pagination/cache coverage.

### 4. Add a single browser bookmark controller

- Add `public/dashboard-bookmarks.js` with a DOM-free controller accepting `onChange`, fetch, clock, and timer functions. Expose idempotent start/refresh, folder disclosure, presentation selection, connect/disconnect, visibility pause/resume, state read, and dispose operations. Construct it once, apply initial mobile/fullscreen presentation before starting, then load saved status, the current tree if configured, and required folder contents. Use same-origin APIs with a 25-second browser request deadline and a bounded JSON response reader.
- Maintain one source generation, one refresh timer, a deduplicated folder queue, and at most four active collection requests. Queue a folder when it is disclosed with all ancestors open, or when a previously loaded folder is due for refresh. Compact initially loads roots, leaving collapsed children unloaded until opened. Desktop and mobile Expanded load all folders through the same queue. Each folder keeps independent loading, empty, error, stale, truncated, last-attempt, and successful-content state.
- Emit usable parent links independently from child folders; a parent folder's bookmark request must not fetch or recursively combine descendant bookmarks. Reconcile tree refreshes by stable IDs, replace tokens, retain matching contents and disclosure overrides, and remove data for deleted collections. Never associate one folder's response with another folder merely because their names match.
- Refresh status/tree and due loaded/disclosed folders every five minutes while the document is visible, using the existing server cache instead of `refresh=1` for routine reads. Coalesce refresh calls and do not enqueue a duplicate folder already queued or active. Failed first requests use the same five-minute retry deadline; repeated toggles, Settings saves, and viewport changes do not bypass it. Provide a per-folder retry action that coalesces explicit retries and affects only that folder.
- Recover `COLLECTION_SELECTION_EXPIRED` by performing one shared status/tree reload and retrying affected still-present folders with renewed tokens. Permit one recovery pass per refresh cycle, not an unbounded reload loop when capacity eviction recurs. If a folder was removed or the renewed token fails again, show a retryable folder status. Preserve successful same-source content during token renewal and bound failed retries to the next normal cycle.
- Before applying any async status, tree, folder, or mutation result, check both operation generation and configuration identity. A detected successful external configuration change clears the old source's data/overrides, cancels its queued work, and loads the new source. Authentication/access-denial states must not be disguised as normal empty results or transient stale fallback.
- Keep connection mutation ownership separate from snapshot reads. Disable competing connect/disconnect actions for the active mutation, pause obsolete read work, and accept the committed PUT's returned status/tree without awaiting all folder loads before completing the action. Only the mutation's owner may clear pending state or restart polling; an older callback must not release a later mutation. A failed PUT/DELETE preserves the prior saved connection and usable browser snapshot, then resumes its eligible reads.
- Pause timers and cancel read work when the document is hidden. On visibility restoration, reload status/tree through the same owner before scheduling due folders. On pagehide with `persisted: true`, pause while retaining snapshots and disclosure state; on persisted pageshow resume without duplicate listeners/timers. Fully dispose on ordinary navigation. Display modes and fullscreen hiding remain presentation inputs, not service re-creation events.

### 5. Render an accessible, state-preserving bookmark tree

- Add `public/dashboard-bookmark-tree.js` for DOM rendering, separate from controller networking. Render nested lists with native `<details>` and `<summary>` disclosure, bounded folder names via `textContent`, real bookmark `<a>` elements, and readable folder status rows. Use normal link navigation and browser context-menu/new-tab behavior; do not add click handlers that turn URLs into application commands. Validate hrefs as HTTP(S) again at the browser boundary.
- Keep keyed folder DOM nodes by `selectionId`, updating bookmark/status children without rebuilding every summary when a sibling finishes loading. Preserve focus and existing disclosure nodes during token refresh and partial responses. Programmatic open-state changes must not feed back into duplicate requests: ignore toggle events whose current open state already matches the controller's selected profile state.
- Expanded profiles open all folders initially; explicit user disclosure choices may override that initial state within their session profile. Compact starts roots open and descendants closed, and opening a child does not automatically open its grandchildren. Switching mobile mode selects that mode's existing override map or its defaults; desktop always selects the expanded profile rather than inheriting mobile Compact choices.
- Show separate unconfigured, loading-tree, no-collections, empty-folder, unavailable, stale, access-denied, and limit states. A failed folder keeps siblings visible, and a transient failed refresh keeps its successful links with a stale label. Loading one folder must not clear the entire tree. Root collection bookmark links remain visible in Compact after loading.
- Keep disclosure controls keyboard-accessible through native Tab, Enter, and Space behavior. Preserve nested list semantics rather than declaring an ARIA tree without implementing its arrow-key model. Use a heading and labeled bookmark region, visible focus styles, and explicit status messages for asynchronous results.

## Acceptance Criteria

- Existing saved Linkwarden connections load a correctly associated parent/child bookmark tree. Direct parent links and child-folder links remain separate, and duplicate folder names do not merge content.
- Desktop initially expands the entire tree in a reserved right-side area without overlapping right- or left-positioned information. Long trees and narrow desktop widths remain usable.
- Mobile defaults to Compact: top-level collections are open, their direct links and child-folder labels are visible, and all descendants start closed. Each disclosure opens only that folder; Expanded reveals all levels initially. Both modes remain keyboard-accessible and fit 320px/390px widths.
- Compact/Expanded and Hide bookmarks in fullscreen save with display preferences and survive reload. Missing/invalid values use Compact and fullscreen hiding disabled. Linkwarden credentials remain outside browser display storage.
- Fullscreen hiding removes the bookmark region and its reserved space on both layouts, then restores the prior profile's loaded contents and disclosure state on exit. Disabled hiding leaves bookmarks visible.
- Stable folder IDs and configuration identities keep refreshes and token recovery source-safe. Only one bounded recovery pass runs per refresh cycle; deleted or unauthorized folders cannot regain content through obsolete responses.
- Folder retrieval and pagination have explicit count, byte, concurrency, and time bounds. Limit/truncation, empty, stale, access-denied, and unavailable states are distinct; one folder's transient failure does not erase its siblings.
- Connect/Disconnect actions are independent from Save preferences, preserve the current configuration on failure, serialize server mutations, and reject late old-source results. A successfully disconnected account stays disconnected.
- Display transitions reuse the bookmark controller and do not create duplicate requests/refresh owners or restart unrelated services. Existing clock/weather/calendar/photo/mobile behavior, documentation, and all required verification remain correct.

## Risks And Decisions

- Existing collection tokens are freshly issued on every tree fetch and can expire or be evicted from a 1,000-entry shared store. Stable IDs handle UI continuity; structured errors and one coalesced recovery pass prevent recursive refresh storms. The 256-folder cap keeps a single tree below token capacity, but multi-browser eviction can still occur and must remain recoverable.
- A configuration identity based on the stored encrypted record distinguishes even rapid same-URL reconnects while surviving restart. Do not use rotating collection tokens, raw access tokens, or second-resolution timestamps as a public source identity. API responses must be guarded after awaited retrieval, not only when requests start.
- Compact is a disclosure policy, not a flat collection selector: roots begin open while descendants begin closed. Expanded is the initial open policy; explicit session disclosure choices are retained separately per desktop/mobile profile. Fullscreen visibility is independent of disclosure and data ownership.
- The current Linkwarden request helper clears its timer before asynchronous JSON consumption finishes. Whole-tree loading amplifies that gap, so bounded body ownership and a total pagination deadline are part of this integration rather than optional cleanup. Server cache bounds prevent expanded trees from turning one installation-wide client into unbounded collection storage.
- The fixed limits intentionally produce visible notices or limit errors for very large accounts rather than silent omission or indefinite loading. Normal accounts within the bounds retain their full hierarchy and results. The configured Linkwarden site remains available as a normal link for content beyond the dashboard budget.
- Hiding bookmarks in fullscreen removes only presentation and reserved space; it does not disconnect Linkwarden or delete cached data. Document visibility still governs automatic request work. Viewport changes may load previously undisclosed, uncached folders when Expanded becomes active, but must not repeat fresh requests or create a second owner.
- A reserved column narrows the existing information area. Desktop right alignment must be local to that column, and wrapping may need scoped adjustments; do not solve overlap with a fixed overlay or by changing saved display scales. Mobile DOM order and existing section identity must remain intact.
