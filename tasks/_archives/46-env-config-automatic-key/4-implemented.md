# implemented

## Outcome

Implemented task 46 on the new branch `46-env-config-automatic-key`, version `0.17.15`. Compose now forwards ordinary application values from `.env`, server startup automatically creates/reuses a persistent integration key, and Home Assistant private trust uses `HOME_ASSISTANT_CA_FILE` directly for scoped WebSocket TLS. Actual user `.env`, keys, databases, certificate files, mounts, and running services were not edited or restarted.

## Changes

- `docker-compose.yml` uses `env_file: .env` instead of repeating ordinary runtime variables. Fixed database/photo container paths remain authoritative; key-path overrides remain supported as container-visible persistent paths. `.env.example` and dedicated setup docs distinguish Compose interpolation from runtime env-file injection and preserve direct/development inherited-value precedence. Compose's default application behavior stays safe; no mount capability, managed NFS deployment, privilege change, or network redesign was added.
- `src/config.js` is now pure validation/projection: explicit secrets are validated, database-relative default key paths and `homeAssistantCaFile` are projected, and config import does not read/create key files. Key initialization moved into owned `src/server.js` startup after CA validation, with store/resource ownership retained.
- `src/linkwarden-key.js` creates required new parents with `0700`, writes/fsyncs a complete `0600` owned temporary key, then exclusively publishes through a same-directory hard link. Race losers read the completed persisted winner; owned temp files are removed. Existing files are never overwritten or permission-normalized. Invalid/read-failed keys, persistence failures, and missing keys for a database containing integration credentials fail startup instead of rotating or reporting ephemeral success. An explicit valid secret wins without key-file I/O. The default filename is unchanged for standard direct/Compose data directories.
- `src/home-assistant.js` uses the supported Undici `Agent`/`WebSocket` API with an owned per-client dispatcher. `HOME_ASSISTANT_CA_FILE` is validated/loaded before registry and service sessions without setting process-global trust or a global dispatcher. Public roots and certificate/hostname checks remain enabled; unrelated HTTPS trust remains unchanged. Owned transport disposal is idempotent and occurs after HTTP work drains, before SQLite closure; injected factories remain caller-owned.
- Undici `8.11.2` is the sole new runtime dependency (declares Node >=22.19.0; project remains Node >=24). Docker installs locked production dependencies at build time, never application startup. Local instructions now include `npm ci`. Package manifests/lockfile agree at `0.17.15`.
- Added `test/startup-key.test.js`, extended key/config/TLS/lifecycle/release checks, and updated copied-source process fixtures to resolve the new dependency without changing their shutdown semantics. Browser global setup now owns a temporary database/key directory and keeps NFS disabled, avoiding a shared default key or accidental user CA reads.
- Added opt-in `scripts/check-production.js` for a clean production-only artifact install/import/readiness/HTTP/key/shutdown check, isolated from the working dependency tree. Generated default key filenames and temporary publications are ignored by Git. Updated README briefly plus existing local/deployment/Home Assistant/Linkwarden/NFS/testing docs; no broad guide, dotenv parser, bundler, runtime installer, public secret API, or settings owner was added.

## Limits And Decisions

Keys beside multiple databases in one directory are intentionally shared by default; independent keys require explicit paths. Existing directory/file ownership and permissions are preserved. Atomic exclusive publication requires filesystem hard-link support; failures stop safely rather than using overwrite or memory-only fallbacks. Moving database/key paths or restoring lost keys remains an operator action, not automatic migration or credential rotation.

Compose ordinary env-file values are not automatically overridden by unrelated shell variables; documented overrides use a Compose override or explicit service override. Generic Node extra-CA configuration remains available to operators, but it is no longer needed or mapped for Home Assistant. No live Home Assistant/Linkwarden/CalDAV account, actual wallpaper scan, NFS mount change, user WebUI restart, archived review remedy, `todo.md` edit, push, or merge is included. The two denied OS-signal probes remain explicit environment exclusions, not silently claimed successes.
