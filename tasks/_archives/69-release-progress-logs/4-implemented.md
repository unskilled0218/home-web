## Outcome

Implemented visible release progress on branch `69-release-progress-logs`, version `0.17.38`, starting from the checked-in task 68 implementation without merging or archiving that task. Local gates display bounded sanitized output as it arrives. Quiet selected commands report elapsed activity every ten seconds; authenticated operations use fixed labels/phases without exposing raw responses. Console backpressure is separated from release supervision, and failure diagnostics no longer slice/replay arbitrary raw tails. No live publication or privileged setup was performed.

## Changes

- Added `scripts/release_progress.py`: independent nonblocking pipe/file descriptors or per-write nonblocking socket sends, a supervisor-owned 64 KiB console queue, continuous worker stdout/stderr drainage through execution and cleanup, and a final console shutdown allowance below two seconds. No sink process inherits the lock or credentials; forwarding uses one owned thread. Ancestor descriptor flags are unchanged. Closed or stalled consumers may lose output but cannot introduce a blocking fallback or hold the checkout lock for delivery.
- Added one sanitizer state per local stdout/stderr stream, complete-record decoding, terminal-control filtering, proxy credential redaction, sensitive assignment suppression, and private-key/configuration-region suppression. Overlong, malformed, or uncertain streams remain suppressed through EOF. Limits are 4 KiB pending line, 1 MiB displayed child text per gate, and an 8 KiB already-sanitized diagnostic tail; display drops and quotas never reset sensitive state. A failed gate may replay only that safe tail if earlier delivery failed and display budget remains. No live publishing token is read for redaction.
- Extended `release-data.py::capture()` with silent-by-default progress observation of stdout/stderr and elapsed ticks, never body/header/stdin data. Original raw evidence buffers, byte limits, command deadlines, exit categories, and owned-process cleanup remain authoritative. The selector continues supervising after output EOF while the child remains alive, preserving heartbeats and timeout enforcement. Added a heartbeat-only `run-progress` action retaining byte-exact command files and reconciliation failure categories.
- Wired real verification gates to live sanitized streaming, safe completion/error context, and unbuffered Python suite execution. Added source/metadata messages, fixed shell phases, heartbeat-only staging/tag/promotion/package/inventory/image work, per-platform Docker runtime command progress, and explicit owned-resource cleanup status. Authenticated command output remains private; command completion does not replace publication readbacks.
- The normal-release lock supervisor owns the console boundary before lock/worker startup and retains it through failure traps, cleanup, auth disposal, and final diagnostics. Worker tool/legacy-state checks now execute inside that boundary after lock validation; argument handling and Python availability still precede supervisor entry. CLI-only paths retain their existing narrow behavior and do not create log state or workers. Standalone progress/gate error messages use the same bounded sink primitive.
- Added `test/release-template/test_progress.py`, extended fake publication ports for delayed builds and sensitive external-output sentinels, copied the new authority helper into owned fixtures, and included it in script identity. Updated README, release operations, testing docs, notes, and all version mirrors without dependency-resolution changes. Existing deployment/application behavior, early no-bootstrap readiness, mandatory immutable-image checks, package/server restrictions, and publication/retry decisions remain unchanged.

## Limits and inherited findings

- Progress is informational, not publication authority or runtime certification. No real AMD64/ARM64 image run, remote Docker backend, live registry push, remote Git write, release creation, package association, privileged bootstrap, or emulation installation was attempted. Task 68's recorded missing ARM64 advertisement remains an operator prerequisite; this task does not infer execution support from historical evidence.
- Sanitization is conservative and may suppress useful text, especially after malformed/oversized records or unclosed configuration dumps. It cannot identify every deliberately encoded secret. Authenticated output remains captured rather than streamed, and the live token is not read to improve local redaction. No new persistent log service/files are introduced by the release feature; verification evidence files above are implementation-owned artifacts.
- Backpressure tests cover supported Linux pipes and sockets, with separate descriptor flags and bounded console shutdown. Missing Python prevents entering the Python supervisor; the preexisting Bash-only prerequisite error remains outside that boundary and holds no release lock. Kernel-level uninterruptible filesystem I/O, SIGKILL, and power loss cannot gain cleanup guarantees from console progress.
- Task 67's independent daemon-cleanup sequencing defect, ambient Node version-probe isolation issue, and missing persistent real-`local()` orchestration regression remain inherited separate work. The new gate/wrapper integration tests and current real verifier run do not claim to repair those broader findings. Archived tasks and `todo.md` remain untouched.
