## Changes

- Added Settings → General → **Settings scope**, with Local as the default and Global as an independent per-profile opt-in. The mode key is separate from Local preferences/location and absent from global snapshots, database preferences, and import/export files. Local startup restores only its own record or valid legacy browser values; shared caches and server settings are not Local defaults.
- Added shared Local/scope/transfer validators in `public/dashboard-settings-data.js`, bounded request/body handling in `public/dashboard-request.js`, and the active-source coordinator in `public/dashboard-settings-scope.js`. Local saves use profile storage; Global saves retain the existing revision-conflict adapter. Removed automatic legacy-to-global initialization and deletion of legacy data by Global reads.
- Routed preferences, local weather selection, pickers, and direct-layout saves through captured source tokens containing mode/epoch/revision. Mode changes retire old work, preserve dirty drafts, and prevent writes into a different source even when numeric revisions match. Storage events synchronize same-profile tabs; independent profiles keep independent mode choices. Quota/read/write failures retain prior confirmed data and drafts. Already-admitted global mutations are not falsely treated as rolled back after a browser source change.
- Updated scope-aware UI feedback, local/shared reload labels, layout token handling, import/export controls, and narrow-panel styling. Local mode retains read-only shared integration content and independent selections, while connection/device-management controls and handlers require Global. Pending Wake actions remain separate and are not dispatched or canceled by a scope change.
- Added a read-only `/api/dashboard/configuration` channel for Local calendar/Linkwarden identity discovery without reading global preferences or adopting global weather location. It uses bounded browser reads and existing observer patterns; Global retains its aggregate observer rather than adding a duplicate metadata owner. Home Assistant/Wake keep their current independent configuration owners.
- Added `src/local-weather.js` and `POST /api/weather/local` for validated, volatile coordinate/timezone queries. Local demand never writes the global location, preference/cache rows, or registrations. The cache retains at most 16 keys/512 KiB of normalized payloads, uses a bounded queue with two active provider requests, coalesces matching demand, and throttles retained-key attempts hourly. Shared provider mechanics now live in `src/weather-provider.js`, preserving fixed URLs, 1 MiB provider bodies, and ten-second deadlines.
- Added Local weather source validation/controllers and explicit weather dispatch. Local labels remain browser-owned, unit changes reproject canonical data, and old-city/global results cannot replace the active source. Missing Local location issues no provider query. Local work is demand-driven; persisted Global weather still refreshes independently without viewers. Shutdown cancels Local timers/queued work, owns actual active provider promises, and retains unsafe deadline outcomes rather than closing SQLite while work remains unconfirmed.
- Added `GET /api/dashboard/photos/local` with strict shared versioned manifest validation, configured enablement independent of preparation availability, eligible-only counts, and producer-side filtering before a 256 KiB UTF-8 serialization limit. Disabled sources do not scan; failed enabled sources remain unavailable; successful all-rejected scans are authoritative empty. Legacy manifests and opaque image streaming remain compatible. The real round-trip test proves a raw legacy body exceeding the cap still produces a valid Local manifest containing its eligible image.
- Added Local photo playback and explicit scope dispatch while retaining Global's server snapshot follower. Local ordering/interval/visibility belong to that browser; Global sequence/revision/deadline do not change. Both share decoding/presentation behavior without another Local metadata polling loop. Source switching retires old players/decodes, confirmed empty/disabled states clear layers, and transient failures retain last-good backgrounds.
- Added strict global settings import/export endpoints and browser download/upload controls. The version-1 portable bundle contains complete preferences and nullable weather location only, capped at 128 KiB with the existing inner preference bound. Import checks both live revisions inside one SQLite transaction, supports explicit null-location clearing, rolls back both components on failure, and notifies weather/slideshow only after commit without extra writes. Shared transaction handling avoids nested `BEGIN`. Notification errors cannot relabel a committed import as uncommitted.
- Global import adoption explicitly invalidates older shared polls instead of coalescing onto an obsolete read. Pending imports reject competing preference saves; late results after a source transition cannot replace Local state. File reads/download URLs are retired on source changes/disposal, conflicts retain the selected file, and imports remain disabled outside confirmed Global mode or while editing.
- Added 26 Node scenarios across scope/storage/epoch, transfer/rollback, Local weather API/service/controller, Local manifest/playback, and shutdown coverage. Added six browser scenarios in two new specs for A-local/B-C-global isolation, independent cities/playback, same-profile dirty drafts, offline shared settings, and actual import/export. Existing shared-behavior specs explicitly opt into Global fixtures, including independent Firefox contexts; new scope specs keep default-Local contexts. Updated old automatic-migration assertions to verify no global publication.
- Added `docs/settings-scope.md` and `docs/settings-import-export.md`; updated dashboard/layout/NFS/testing documentation and the concise README settings summary. No user configuration, live integration account, real NFS mount, or `todo.md` was changed.

## Limitations and decisions

- Browser execution remains blocked by the missing Playwright executable. The operator must run `npx playwright install chromium firefox`, then rerun `npm run test:browser`. No browser/system packages were installed. Actual cross-browser rendering, accessibility/geometry, downloads/uploads, and UI lifecycle assertions remain unverified in this environment despite passing Node/controller/API coverage.
- Local means one profile/origin, including its tabs, not a per-tab flag or server account. Truly simultaneous local-storage writes retain last-successful-write semantics; already-changed revisions and cross-source tokens are guarded. Clearing site data removes Local values/mode.
- Global persisted settings remain available only to explicitly Global browsers. Local source values are never uploaded merely by joining Global. Legacy initialization remains available at the server compatibility endpoint for older callers but is not invoked by updated clients.
- Integration accounts, managed devices/history, and NFS topology remain installation resources. Their mutation controls require Global mode in this UI; mode is not server authorization. Normal Wake actions retain their separate explicit action contract. Settings transfers exclude credentials, inventory/history, mounts, caches, temporary URLs, and every browser's mode.
- Local weather caches are volatile and demand-driven; their hourly attempt policy applies while a key is retained, and inactive keys may be evicted. Global weather/hourly work and server photo rotation remain independent. Local manifests intentionally project the existing accepted library pool rather than expanding its safety limits or filtering only after reading an oversized raw body.
