## Changes

- Created branch `76-remove-general-scope-selector` from the committed plan/review state. Removed General's generated Local/Global selector and scope status while retaining seven widget selectors. General updates are explicitly safe without a control. General retains transfers, recovery, and accessible keyboard navigation; its description no longer instructs users to choose a scope.
- Preserved all eight internal category owners, the existing scope-map schema and legacy seeding, both raw preference stores, and General's saved layout ownership. Fresh layouts remain Local; existing Global layouts remain Global. Direct layout editing, captured tokens, profiles, geometry, retained position/scale, and opposite-store isolation remain unchanged. No startup migration, automatic scope rewrite, or replacement selector was added.
- Added coordinator-owned transfer preparation independent of General mode and Local revision. A valid selected file captures a fresh validated raw Global preference/weather revision pair and a generation/map-bound admission token. Active Global synchronization reuses its existing read; all-Local pages perform a bounded cancellable one-shot request without publishing Global preferences into their Local projection or starting Global preference polling. The existing shared reader now returns its accepted snapshot to callers rather than requiring transfer preparation to infer success from a previously confirmed cache.
- Retained strict pre-dispatch persisted-map checks, revision validation, duplicate/import/action exclusion, normal Global-write blocking, and unrelated Local-save independence. Corrupt or unreadable admission maps immediately publish recovery state and report the normalized scope error. Invalid snapshots, unavailable weather revisions, superseded reads, deadlines, disposal, and malformed committed responses cannot establish or publish transfer authority. Existing server endpoints, host/origin checks, file limits, and SQLite transaction behavior are unchanged.
- Updated transfer controls to prepare only validated files and enable explicit Global import without a General selector. File/preparation generations reject obsolete completions; failure retains the selected file. Reload explicitly fetches a new preparation baseline instead of silently rebasing through polling. File replacement is disabled during export/import, while a replacement file can supersede pending preparation. Successful imports adopt confirmed Global state through the existing owner, preserve Local records/maps and layout ownership, and consume the preparation token.
- Added Node control/coordinator coverage for seven visible selectors versus eight policy owners, all-Local and mixed preparation, read coalescing, raw revisions, no lasting preference polling, Local revision independence, stale/corrupt/unreadable maps, work exclusion, retained files, explicit retry, canceled/superseded work, deadlines, disposal, and rejected committed responses. Browser tests retain saved Local/Global layout contexts instead of toggling removed UI, update General's keyboard focus expectation, and exercise all-Local preparation failure, explicit Reload, weather-only conflicts, successful import, and unchanged ownership without recurring Global preference reads.
- Updated README, dashboard/layout/scope/transfer documentation, versioned release notes, and synchronized release metadata to `0.17.45`. Historical task documents and prior versioned release notes were not rewritten.

## Limits

- This removes General's visible scope choice, not its internal compatibility entry. New clients cannot switch layout ownership through Settings. Existing saved mode, fresh Local default, and explicit corrupt-map recovery remain authoritative; no layout-store migration or winner policy was introduced.
- One-shot all-Local preparation does not write browser storage. Reused active Global reads retain their existing confirmed-cache behavior, and successful explicit imports may update the shared confirmed cache. Neither operation overwrites Local preferences, follow choices, or category maps.
- Captured revisions remain fixed until explicit Reload/file selection; background polling does not silently repair a stale import. A timeout or malformed response after dispatch can leave an uncertain server commit outcome, so users must inspect/reload Global state before retrying. Client scope checks are not server authorization or an atomic cross-tab lock.
- Verification covers the configured Chromium suite plus its two dedicated Firefox scenarios, not every transfer case independently in every browser. The intermediate browser timeout/crash remains recorded despite the final successful repeated and full runs.
- Unrelated integration-draft discard and Calendar auto-close behavior remains unchanged. No merge, push, deployment, or release publication was performed.
