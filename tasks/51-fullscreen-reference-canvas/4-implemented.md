## Outcome

Implemented task 51 on the newly created branch `51-fullscreen-reference-canvas`, version `0.17.20`. Custom widgets now project into an estimated/confirmed fullscreen reference canvas, which fits the current usable destination with one uniform scale for positions, dimensions, text, padding, and controls. Windowed tools and caption/status changes no longer independently stretch the layout axes. Settings uses the same accepted reference pixels and freezes reference updates until the dialog closes. Automatic layout, normalized version-2 records, and existing shared persistence ownership remain unchanged.

## Changes

- Added `public/dashboard-layout-reference.js` as a pure, storage-free reference owner. It validates CSS screen dimensions, falls back to the initial valid layout viewport when necessary, derives both profile references with their margins and fixed reservations, retains fullscreen confirmation after exit, detects reported screen/orientation changes, and queues the latest context while Settings holds a lock. Reference entries are immutable local presentation data, not preferences or a new browser cache.
- Added pure `fitLayoutCanvas()` to `public/dashboard-layout.js`. It caps scale at 1 and anchors the fitted canvas bottom-left, leaving excess space above/right. Existing projection minima and field-specific edit math remain unchanged; they operate in reference space, with no second minimum clamp against the fitted destination.
- `public/dashboard-layout-view.js` now separates destination measurement from accepted reference access. The existing stage has reference dimensions and one left-bottom-origin transform. Live nodes retain their identities, handlers, focus, layers, hidden flags, and scrolling. Existing card padding variables stay in reference pixels. Automatic restoration clears stage transforms/dimensions and existing card overrides.
- The view owns orientation/fullscreen/resume observations and the existing coalesced animation frame. Each fullscreen-entry calibration uses a bounded 12-frame sampling window, publishes once only when the final two observations agree, rejects keyboard/pinch observations, and stops on exit/disposal. Context changes during fullscreen can start a new calibration; ordinary destination resizes cannot recalibrate a settled reference. There is no permanent measurement polling loop or new service timer.
- `public/dashboard-layout-editor.js` uses the selected profile's accepted reference for fields, min/max constraints, preview, and fixed-start pointer conversion. The actual destination still gates zero-area editing. Preview-scale/profile/context changes cancel gestures safely; destination-only fitting does not rewrite their canonical coordinates. `public/dashboard.js` acquires the reference lock before Settings draft initialization and releases it after gesture cancellation on close. Existing pending saves, conflicts, dirty-state policy, and integration credentials remain separately owned.
- Addressed the plan-review R2 Warning in `public/dashboard.css`: custom weather values have a stable flex policy and forecast temperatures wrap independently of `bookmarks-shown`. Automatic-mode selectors and fullscreen bookmark hiding remain intact. The task 50 padding/border-floor protections are preserved.
- Added six pure reference/fitting tests and four view lifecycle/fitting tests, retaining the original model, schema, migration, and view checks. Extended the browser layout spec from 16 to 22 scenarios, adapting existing assertions to reference projection plus uniform fit rather than removing minimum/containment coverage. The touch-resize regression now explicitly narrows the panel enough to change preview scale while requiring unchanged reference pixels.
- New browser coverage checks actual canvas/card rectangles, scaled clock text, mismatched aspect ratios, estimated versus real fullscreen sizes, repeated entry/exit, invalid screen fallback, safe-area/status/caption destination changes, locked Settings during display/fullscreen updates, and no presentation-induced PUT/revision changes. Direct tiny-reference cases retain one-pixel padding and subpixel-preview regressions alongside tiny-destination fitting.
- Deterministic and real Fullscreen API weather cases compare forecast line counts and normalized child geometry, not just outer rectangles. They preserve bookmark hiding/restoration and unchanged stored preferences while checking stable weather flex/wrapping. Existing Automatic, pointer/touch, scrolling, pending stubbed Wake, selected readings/bookmark navigation, slideshow/clock ownership, cache, and cross-browser sharing cases remain meaningful.
- Updated `public/index.html` labels/help and dedicated dashboard/testing documentation for reference CSS pixels, fixed reservations, uniform content scaling, first-confirmation correction, local reference lifetime, dialog locking, profile changes, and compatibility. Both package manifests now identify `0.17.20`; dependencies and persistence schemas are unchanged.

## Investigation and Limits

Firefox correctly provided a different native fullscreen viewport from its configured window size. Initial tests incorrectly hard-coded Chromium's fullscreen dimensions; expected reference dimensions now derive from each browser's actual fullscreen layout viewport and the documented reservations. A normalized-text comparison also magnified tiny screen-space rounding differences after dividing by a small scale; it now asserts the same 0.1px rendered CSS-pixel tolerance used for geometry. These corrections retain checks for actual uniform content scaling rather than weakening them to CSS declarations alone. A helper was also corrected to require zero boxes for intentionally hidden bookmarks while continuing to validate their layer styles.

Before first fullscreen, screen dimensions remain an estimate. Actual fullscreen confirmation can correct reference pixels once for that entry, without rewriting canonical geometry. Reference state lives only in memory; reload starts estimation again. Reported screen/orientation changes invalidate a confirmation, but same-sized displays without distinguishing metadata cannot reliably be distinguished without additional permissions. None are requested. Fixed reference status/caption bands may leave unused fullscreen space, as specified in the plan.

Uniform fitting scales text and control targets down as well as card geometry. Tiny windows guarantee containment and recovery, not readability. The controlled screen/visual viewport fixture tests measurement deterministically, not hardware, browser chrome, or Safari behavior. Native Fullscreen API coverage complements it. Session locking prevents measurement-induced coordinate rebasing; it does not resolve task 49's inherited polling-induced numeric-input loss/gesture-cancellation warning, which remains explicitly separate.

No database/cache migration, resize/fullscreen autosave, runtime dependency, legacy layout change, user configuration/data edit, live provider access, real Wake dispatch, NFS mount, or `todo.md` edit was performed. Fixtures own their temporary servers/storage and provider actions. No push, merge, release, image build, or publication was performed. Implementation and results are committed together on the task branch.
